# BOSS 求职助手

本地 PyQt6 桌面程序：AI 根据求职目标操作 BOSS 期望职位和原生筛选，从推荐入口读取候选、查询公司背景、结合已确认简历评分并生成招呼语。每次根据工具实际结果决定下一步，不使用 embedding 或向量数据库。

## 启动

需要 Windows、Python 3.11 或以上、已安装的 Chrome，以及提供 Chat Completions 接口的模型服务。

```powershell
uv sync
uv run python -m boss_say_hello
```

已有虚拟环境时也可运行 `.venv\Scripts\pythonw.exe -m boss_say_hello`。首版不包含 exe 安装包。

## 使用顺序

1. 点击顶部“打开 BOSS 登录”，在独立浏览器中手动登录。程序自动检测，也可点“检查登录状态”。登录状态保存在独立浏览器目录。
2. 在“配置与提示词”填写 API 地址、模型名、密钥，点击“连接测试并保存”。成功后密钥自动保存至系统凭据，下次启动自动恢复；眼睛按钮切换显示，保存不清空输入框。普通配置和提示词修改后自动保存。
3. 导入本地 PDF，使用当前界面中的 API 配置，不必先手动保存。核对原文、关键词、经历摘要，修改后点击“确认使用本版本”。关键词和摘要的未确认草稿也会自动保存、重启恢复。支持有文本的 PDF，不支持扫描件、加密文件或 OCR。
4. 填写期望职位、一个城市、完整税前月薪区间；按需配置平台经验、学历、行业、规模等原生条件。职位名称应与平台分类相符。配置优先于三个可编辑提示词中的冲突内容。
5. 在“岗位与运行”点击开始。默认只生成预览；步骤区显示每个动作、理由及真实结果，岗位详情包含公司来源、背景分、综合分和招呼语。“本地历史”保留之前运行。

原生薪资可自动选择覆盖目标区间的一档；跨档位时需在界面明确选一档，不会自动替换为不限。已有同职位/城市期望会复用，不自动覆盖原有账号薪资；新增期望只有字段与配置完全一致才允许保存。平台实际控件尚待共同验收；无法识别或回读时明确停止，不把未筛选列表当作成功。

公司查询目前要求 Moonshot 官方地址（`https://api.moonshot.cn/v1` 或 `.ai/v1`），需要账号具备搜索服务权限。外包检查默认开启，有来源支持的外包、驻场、派遣嫌疑即排除；关闭后仍核对主体和其他背景。没有搜到外包信息不等于通过，身份或用工证据不足标待确认。默认岗位占 80%、背景占 20%，综合分由程序计算。默认每轮候选 30、决策 300、单岗位 12、每公司查询 3，均可修改并保存。公司判断由 AI 对公开资料作有限评估，不能保证穷尽所有业务或风险。

薪资区间有交集即保留；面议、日薪、年薪等不能明确换算的值标记待确认，不会自动发送。模型输出无效、评分失败、分数不足或已联系的岗位不会发送。

## 自动发送与暂停

每次启动，自动发送和附件开关均关闭。开启自动发送后，点击开始才会启动本轮；每轮配置与简历固定，运行期间修改配置只影响下一轮。每轮上限默认 20、最低分 70、间隔 30 秒，可修改。

首次联系可能触发平台默认招呼语。程序只有在能核实平台首次联系行为、消息长度和目标会话时才允许发送；无法确认会显示原因并阻止操作。平台改版可能导致适配失效。当前已经验证登录与推荐详情的只读路径，**真实发送、平台消息限制与附件控件尚未验证，自动发送可能被能力检查阻止**。不要把离线测试通过当成平台发送验证。

附件是独立开关，必须选择平台已存在的简历；导入本地 PDF 仅用于分析，不会自动上传。当前页面不能读取附件列表时，保持关闭。

暂停会阻止后续动作，已发起动作会记录结果。继续保留本轮配额和快照；部分已联系岗位不会自动补发剩余步骤。超时、中断或送达证据不足记为未知，占用配额并禁止自动重试。重新打开程序只恢复记录，不恢复自动运行。

## 本地数据与模型上下文

本地工作目录为程序目录下的 `workspace`（当前源码运行时为 `E:\Boss\boss_say_hello\workspace`），配置页提供目录入口。首次切换会复制旧 `%LOCALAPPDATA%\BossSayHello` 中的配置、历史、简历、日志和浏览器登录数据，保留原件，不覆盖已经存在的新工作目录。迁移前应关闭旧程序及其浏览器。

- `config/settings.json`：城市、薪资、模型地址/名称、三个完整默认提示词及运行参数。
- `config/resume_draft.json`：未确认的关键词和经历摘要编辑草稿，确认成功后清除。
- `history/jobs.json`：按账号及岗位整理浏览记录、评分、招呼语草稿和发送结果，区分已发送与结果未知。
- `history/companies.json`：公司查询原始来源缓存，默认有效 7 天；新一轮重新判断，不复用可发送结论。
- `records.sqlite3`：完整简历版本、运行快照、历史和发送去重凭据。JSON 由此生成，缺失时可恢复。
- `resumes`、`browser_profile`、`logs`：本地简历受管理副本、登录数据、运行日志。

API 密钥仅保存到 Windows 系统凭据，不写入 JSON。系统凭据不可用时会明确提示下次需要重新输入。连接失败不会覆盖此前有效的已保存密钥。关闭时会等待配置及简历草稿保存完成。

“模型等待时间”默认 180 秒，可在配置页调整为 10—1800 秒并自动保存在本地；旧配置自动使用默认值。它控制模型响应数据的读取超时，连接超时独立为 15 秒。修改只影响下一次操作或新一轮任务。评分超时不会进入招呼语发送步骤。

密钥按 API 地址隔离。切换服务地址后，不会自动把旧服务密钥用于新服务；需要输入并保存对应密钥。早期未绑定地址的凭据不会自动迁移，需重新保存一次。

PDF 提炼会将提取的原文发送给你配置的模型 API；评分和招呼语使用确认后的关键词、经历摘要、岗位文本和三个提示词，不上传 PDF 附件给招聘者。连接测试仅发送短测试文本，不包含简历。请在界面确认 API 地址后再导入。

项目 docs、所有 env 文件、真实简历、Cookie、浏览器 profile 和运行记录均不应进入 Git 或分发包。项目不提供 env 示例，也不从 env 文件读取应用配置。

## 运行日志与必填提示

“运行日志”页实时显示登录检测、PDF 提取、模型请求、岗位筛选、评分、发送意图与结果、暂停/继续及异常记录，可筛选 DEBUG / INFO / WARNING / ERROR，或打开日志目录。清空显示不会删除文件。未处理异常会请求暂停并记录错误位置。

日志位于 `workspace\logs\application.log`，每个文件 5 MB，最多保留 5 个备份。包含时间、线程、任务/岗位/步骤标识、状态、耗时、HTTP 状态码、异常类型链和代码位置；不记录密钥、Cookie、完整 API 地址、简历或岗位正文、招呼语文本、异常原始消息。详细业务内容仍在本地历史中查看。

必填项以红色 `*` 标示；测试连接或开始任务时，缺失的 API 地址、模型名称会标红。没有对应已保存密钥时需填写密钥；简历关键词和摘要不能为空。开始本轮还要求职位、单一城市及完整薪资区间，连接测试不要求这些目标。启用附件发送时必须选择平台附件。发现首次沟通会附带平台默认招呼语时，本轮先暂停并显示提示，阅读后点击“继续本轮”才允许联系。

## 开发验证

```powershell
uv run pytest -q
uv run python -m compileall -q src/boss_say_hello
uv run python scripts/check_release_files.py --staged
uv run python scripts/check_release_files.py --tracked
```

普通测试使用合成数据和假浏览器、假模型，不发送真实消息。可选本地 Chrome DOM 测试：设置本进程变量 `$env:BOSS_TEST_LOCAL_CHROME='1'` 后运行 `uv run pytest tests/test_dom_browser.py -q`，只打开合成 HTML；此变量不是 env 文件。构建 wheel 后用 `--package <wheel路径>` 检查分发条目。提交应使用明确文件清单，不使用强制添加忽略文件，不自动上传。
