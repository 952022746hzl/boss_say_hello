# BOSS 求职助手

一个在 Windows 上运行的桌面程序。登录 BOSS 后，选择账号已有的求职标签，程序会逐个查看岗位、查询公司背景、结合你的简历评分，再生成招呼语。

**“自动发送”默认勾选。** 仍需点击“开始本轮”才会实际执行，打开程序不会自行运行。只想预览时，先取消勾选；程序会记住你的选择。

## 1. 安装和启动

可以用打包好的 exe，也可以从源码启动。两种方式都需要联网使用 BOSS 和模型服务，并准备好 API 地址、模型名称和密钥。

### 使用 exe（不需要另装运行环境）

适用于 Windows 10 / Windows 11 的 64 位电脑。把完整的 `BossSayHello` 文件夹放在自己可以读写的位置，然后双击里面的 `BossSayHello.exe`。

包内已包含 Python、PyQt、相关库、运行所需的 VC++ DLL 和免安装浏览器，**不需要安装 Python、uv、pip、Chrome 或 ChromeDriver，也不需要配置环境变量**。请完整保留 `_internal` 和 `browser` 文件夹；只复制 exe 无法运行。

首次启动会在 exe 旁创建 `workspace`，用于保存配置、缓存、简历和历史。以后双击同一个 exe 即可继续使用。通过快捷方式启动，数据位置也不会改变。

### 从源码启动

需要 Python 3.11 或以上版本，以及本机 Chrome 浏览器。下面的安装命令只用于源码运行或自行打包，使用 dist 中的成品不用执行。

第一次使用：打开 PowerShell，进入项目目录，依次执行：

```powershell
Set-Location "E:\Boss\boss_say_hello"
python -m pip install uv
uv sync
uv run python -m boss_say_hello
```

如果项目放在其他位置，把第一行的路径换成实际目录。已安装 uv 时可以跳过第二行。

以后启动只需执行：

```powershell
Set-Location "E:\Boss\boss_say_hello"
.venv\Scripts\pythonw.exe -m boss_say_hello
```

如果窗口没有出现，改用下面这条命令，可在终端看到启动错误：

```powershell
.venv\Scripts\python.exe -m boss_say_hello
```

### 自己打包 exe

在 Windows x64 上安装 64 位 Python 和 uv 后，双击项目根目录的 **`build.bat`**。脚本会安装锁定版本的依赖、下载固定版本的官方 Chrome for Testing、核对 SHA256 并打包。首次构建需要联网下载依赖和浏览器；运行成品时不会临时下载运行环境。

构建最后会用发布包相同的代码归档，在独立副本和精简环境中检查 Qt、PDF、TLS、系统凭据后端、模型 SDK 及内置浏览器。浏览器只访问合成页面，不登录 BOSS、不调用真实模型、不发送消息。检查通过后窗口才会显示打包完成。

也可以在 PowerShell 中执行：

```powershell
.\build.bat
```

输出结构如下；每次打包都会生成一个新目录，不覆盖旧版本和其中的数据：

```text
dist/
  本次构建时间-编号/
    BossSayHello/
      BossSayHello.exe
      _internal/
      browser/            ← 内置免安装浏览器及原版资源，不能删除
      README.md
      workspace/          ← 首次运行后自动生成，不包含在打包结果中
```

发送程序给别人时，复制打包后尚未运行过的整个 `BossSayHello` 文件夹。构建脚本会检查打包内容，拒绝包含 docs、env 或个人运行数据。

浏览器版本和来源记录在 `browser/runtime.json`。随包浏览器不依赖系统 Chrome 的版本；更新浏览器时需更新构建脚本中的版本和校验值，再重新打包。

升级时，先结束本轮并关闭程序及其 BOSS 浏览器，再把旧程序旁的整个 `workspace` 复制到新 exe 旁。不要只复制 `settings.json`，否则历史和防重复发送记录不会一起转移。换电脑时 API 密钥需重新填写，因为它保存在原电脑的 Windows 系统凭据中。

## 2. 第一次使用，按这个顺序操作

1. **登录 BOSS。** 点击顶部“打开 BOSS 登录”，在打开的 Chrome 中手动登录。顶部应显示已登录；没有更新时点“检查登录状态”。后续会复用这个浏览器的登录状态。
2. **连接模型。** 在“配置与提示词”中，先填写 API 地址，再填模型名称和密钥，点击“连接测试并保存”。模型名称按服务商提供的名称填写。密钥旁的眼睛按钮可以切换显示与隐藏，保存后不会清空。
3. **选择求职标签。** 点击“刷新标签”，从“BOSS 已有求职标签”下拉框选择，例如“全栈工程师（深圳）”。程序会带出城市。没有合适的标签时，先在 BOSS 中手动添加，再回来刷新。程序不自动新增期望职位，也不操作标签下方的经验、学历、行业等筛选条件。
4. **填写薪资和偏好。** 薪资填写税前月薪整数，单位是元，例如 `20000` 至 `30000`，不要填 `20K`。每轮选择一个城市，须与所选标签一致。三个提示词已有默认模板，可以直接使用或修改。
5. **导入并确认简历。** 在“简历确认”中点击“导入 PDF 简历”。检查 AI 提取的关键词和经历摘要，修改后点击“确认使用本版本”。以后修改内容，也要重新确认。支持可复制文字的 PDF，暂不支持扫描件、加密 PDF 或 OCR。
6. **开始本轮。** 进入“岗位与运行”，点击“开始本轮（使用当前配置）”。只想先查看效果时，请先取消勾选“自动发送”，再开始本轮；查看几个岗位的评分、背调和招呼语。

红色 `*` 表示必填。配置、提示词及简历编辑草稿会自动保存在本地，下次打开不用重新填写。密钥在连接成功后保存到 Windows 系统凭据；如果保存失败，界面会提示。

## 3. 常用设置怎么填

| 设置 | 作用和建议 |
|---|---|
| 城市、薪资 | 填写本轮目标。岗位薪资与期望区间有交集就保留；“面议”等无法明确判断的薪资会标记待确认，不自动发送。 |
| 最低匹配分 | 默认 70 分。达到门槛且其他检查通过，才进入后续招呼语处理。 |
| 每轮成功发送目标（岗位数） | 默认 20 个，可设为 150 等数值。只统计已核实文字招呼语发送成功的岗位；同公司不同岗位分别计数。失败或结果未知不计入成功数。 |
| 联系间隔 | 默认 30 秒。控制联系节奏，实际还会花时间读取页面和等待模型。 |
| 自动发送 | 首次默认开启；后续恢复上次保存的选择，不再因重启强制关闭。点击开始新一轮才执行。 |
| 外包检查 | 默认开启。有资料支持的外包、驻场或派遣嫌疑就排除。关闭后仍会检查公司主体和其他背景。 |
| 背景评分权重 | 默认 20%，岗位匹配占 80%。程序按权重计算综合分。 |
| 模型等待时间 | 默认 180 秒。模型较慢时可适当调大；超时不代表消息已发送。 |
| 单岗位处理 | 正常通过时只调用一次综合评估、一次招呼语生成。格式不合格最多纠正一次，异常情况下仍有单岗位 12 次 AI 处理上限；没有每轮候选数上限。 |
| 公司资料缓存 | 永久保留查询资料和查询时间。同一家公司复用资料，每个岗位仍重新评分和判断外包；不会直接沿用上次“可以发送”的结论。 |

填写的城市、薪资和运行开关优先于提示词里冲突的描述。**每轮开始时会固定当时的配置和简历；运行中修改配置，只影响下一轮。**

三个提示词可以理解成给 AI 的工作说明：

- **求职偏好：** 说明你更想做什么。例如“优先 Java 后端、全栈或 AI 应用开发；希望参与产品研发”。
- **评分标准：** 说明哪些条件更重要。例如“重点考虑实际项目经历和技术栈匹配；简历未提及的技能不要当作已掌握”。
- **招呼语风格：** 说明如何表达。例如“简短自然，结合岗位提一两段真实经历，不夸大，不堆砌技能”。

想重新使用模板时，切换到对应提示词页，点击“恢复当前提示词的默认模板”。

## 4. 程序每轮会做什么

选择已有求职标签 → 读取推荐岗位 → 逐个处理岗位：

**读取详情 → 检查城市和薪资 → 查询公司背景 → 评分 → 生成招呼语 → 按开关决定是否发送 → 下一个岗位。**

一个岗位处理完才进入下一个，不会先背调整批公司再统一发送。设置成功目标为 150 时，程序会继续筛选更多候选，直到确认成功发送 150 个岗位或当前列表没有更多岗位。失败和未知不凑数；页面异常、登录失效、模型服务请求失败或未知发送结果会暂停等待处理。沟通后推荐列表可能刷新，程序会重新核对列表，清理已经失效的候选。

读取详情、查询公司、检查条件、立即沟通和发送由程序依次推进，不再每一步都询问 AI“下一步做什么”。AI 只负责一次综合评估（岗位匹配、公司背景、外包判断），以及通过后的一次招呼语生成。一个正常合格岗位从原来的 6 次模型调用减少到 2 次；公司搜索另计 0～1 次，重试或招呼语超长压缩会增加请求。

同一程序实例内，模型调用和公司搜索共用一个请求队列，同时最多处理一个请求。运行、连接测试、简历提取互斥，连接测试不能连点；普通配置保存和历史查看仍可用。其他程序或其他副本共用同一模型账号，仍可能影响账号额度。

公司背景通常做一次综合查询，已有缓存时复用资料。当前联网背调接入 Moonshot 官方服务，API 地址需为 `https://api.moonshot.cn/v1` 或 `https://api.moonshot.ai/v1`，账号需要具备搜索权限。连接测试通过只代表模型接口可用，不代表搜索权限已核实。

背调会参与评分。证据不足时标记待确认；没有搜到外包信息，不会直接等同于“确定不是外包”。已有联系记录、评分失败、条件不符或发送结果未知的岗位，不会自动重发。

招呼语使用已确认的简历和当前岗位信息。页面有明确称谓时沿用称谓；只有可用姓名时可以使用“姓氏＋老师您好”；信息不足时用“您好”。正文会做长度检查。

本地 PDF 仅用于提炼简历，**当前只发送文字招呼语，不提供平台简历附件发送功能**。PDF 提取的原文会发送至你填写的模型 API，后续评分主要使用确认后的关键词和经历摘要。

## 5. 自动发送、暂停和结束

准备实际联系时，先结束预览轮次，在配置页勾选“自动发送”，再开始新一轮。首次沟通可能触发 BOSS 默认招呼语；如果程序提示确认，请阅读说明后点击“已知晓，继续自动发送”。

- **暂停：** 阻止后续动作。已经发起的模型请求或页面操作可能仍需返回并记录结果。
- **继续本轮：** 继续使用本轮原来的配置、简历和成功发送进度。
- **结束本轮：** 结束这次任务，清理临时状态，保留已浏览岗位、评分、草稿和发送历史。

模型服务临时限流时，程序默认等待 10 秒、20 秒，各重试一次；服务端给出等待时间时优先采用，超过 60 秒则暂停。仍失败会**暂停并保留本轮**，处理后点击“继续本轮”即可。余额或每日额度不足时直接暂停；限制原因不明且没有有效重试时间时也直接暂停。等待重试期间也能暂停或结束；程序不会因模型重试而重复点击发送。

运行页分别显示“成功发送 / 目标”、联系尝试、已发现和已处理数量；日志会记录具体结束原因。“已发送”需要页面回执支持，不能只看“工具执行完成”。请在岗位详情查看联系和消息各自的结果；结果未知时先到 BOSS 手动核实，程序不会自动补发。

结束本轮时，已经发起的模型请求或页面操作可能还需要返回。等待日志出现“本轮任务结束”、后台清理完成后，“开始”按钮会恢复；不会在旧任务尚未退出时启动另一轮。

## 6. 数据存在哪里，遇到问题怎么看

配置页的“打开工作目录”可以打开本地 `workspace` 文件夹。**位置固定：exe 启动时在 exe 旁；源码启动时在项目根目录下。** 从其他终端目录或快捷方式启动，也会使用同一个位置。程序不再自动读取或导入旧 AppData 目录中的数据。

| 位置 | 保存的内容 |
|---|---|
| `config/settings.json` | 求职目标、模型设置、提示词和运行参数；不含密钥 |
| `config/resume_draft.json` | 尚未确认的简历编辑草稿 |
| `history/jobs.json` | 浏览过的岗位、评分、招呼语及发送结果 |
| `history/companies.json` | 公司查询资料缓存 |
| `records.sqlite3` | 完整简历版本、运行历史及防止重复联系的记录 |
| `resumes/`、`browser_profile/` | 简历副本和浏览器登录状态 |
| `logs/application.log` | 运行日志 |
| `logs/ai_requests/` | 完整 AI/搜索请求 JSON、请求编号、每次尝试的耗时、状态与可用的 Token 用量 |

不要随意删除整个工作目录，否则会丢失配置、登录状态和去重记录。API 密钥单独保存在 Windows 系统凭据中；更换 API 地址后，需要填写新服务对应的密钥。

在“运行日志”页，平时选“进度与异常”。排查问题时选“全部”或“DEBUG”，并勾选“显示诊断字段”，可看到模型等待、页面读取、控件操作、耗时和错误位置。清空当前显示不会删除日志文件。

日志页下方可选择一个请求，查看**完整 JSON 正文和本地文件位置**，不会按进度区的行数上限截断。正文包括实际发出的提示词、简历上下文、岗位与公司资料、模型和参数；密钥、认证头和 Cookie 不写入。一次逻辑调用使用同一请求编号，重试标记为第 2、3 次尝试，避免把多条日志误当成多个并行请求。完整请求默认保留最近 500 个、合计约 100 MB，正在处理的请求保留至完成。

常见提示：

- **401 / 身份验证失败：** 核对 API 地址和该服务的密钥，重新连接测试。
- **400 / 请求参数被拒绝：** 核对模型名称及服务支持的请求参数。
- **429 / 请求受限：** 查看日志里的具体分类。临时频率限制会短暂等待重试；余额或每日额度不足，需要先处理账户限制。暂停期间请保持程序打开，才能继续当前这一轮。
- **模型超时：** 查看网络和服务状态，必要时增加模型等待时间，再开始新一轮。
- **模型服务请求失败后暂停：** 网络恢复后可继续原轮次；如需修改 API 地址、模型或密钥，请结束本轮，修改并测试连接后再开始。当前轮次使用的是开始时固定的配置。
- **页面控件或目标身份无法核实：** 查看 BOSS 浏览器是否登录失效、出现验证或页面已变化。处理后再继续，不要把这条提示当成已发送。

## 开发与本地验证

```powershell
uv run pytest -q
uv run ruff check src tests
uv run python scripts/check_release_files.py --staged
uv run python scripts/check_release_files.py --tracked
```

普通测试使用合成数据、假浏览器和假模型，不会发送真实消息。可选 Chrome 页面测试也只打开本地合成 HTML：

```powershell
$env:BOSS_TEST_LOCAL_CHROME='1'
uv run pytest tests/test_dom_browser.py tests/test_dom_contact.py -q
```

所有 `docs/` 目录、任何 env 文件、真实简历、登录数据和工作目录内容都只留本地，不得提交或上传。项目通过界面配置，不需要创建 env 文件。
